# ArtFlowBot Database Migration Plan

## Purpose

Добавить публичные поля конкурсов, необходимые ArtFlowWeb, не нарушая
текущую работу ArtFlowBot v1.1.

## Migration file

`migrations/001_add_web_fields_to_competitions.sql`

## New fields

- `event_date`
- `application_deadline`
- `city`
- `short_description`
- `directions`
- `poster_url`
- `rules_url`
- `is_published`
- `updated_at`

Существующие поля таблицы `competitions` не удаляются и не переименовываются.

## Before migration

1. Убедиться, что актуальный код ArtFlowBot находится в GitHub.
2. Создать резервную копию production PostgreSQL.
3. Зафиксировать количество записей в таблице `competitions`.
4. Проверить несколько существующих конкурсов и их данные.
5. Не деплоить код, использующий новые поля, до выполнения миграции.

## Test database procedure

1. Создать отдельную тестовую PostgreSQL-базу.
2. Создать текущую схему ArtFlowBot.
3. Добавить несколько тестовых конкурсов со старыми полями.
4. Выполнить миграцию.
5. Выполнить миграцию повторно и убедиться, что `IF NOT EXISTS`
   предотвращает ошибки.
6. Проверить наличие всех старых и новых столбцов.
7. Убедиться, что старые конкурсы сохранились.
8. Убедиться, что для старых конкурсов `is_published = FALSE`.
9. Проверить запуск ArtFlowBot и существующие операции с конкурсами.

## Production procedure

1. Остановить изменения конкурсов на время миграции.
2. Создать резервную копию Railway PostgreSQL.
3. Выполнить миграцию один раз.
4. Проверить структуру таблицы.
5. Проверить количество и содержимое старых конкурсов.
6. Запустить ручное тестирование ArtFlowBot.
7. Только после успешной проверки добавлять функции работы с веб-полями.

## Rollback plan

Если миграция завершилась с ошибкой до `COMMIT`, PostgreSQL должен отменить
транзакцию.

Если ошибка обнаружена после успешного применения:

1. Не удалять старые данные.
2. Остановить деплой нового кода.
3. Вернуть предыдущую версию приложения.
4. При необходимости восстановить резервную копию.
5. Новые столбцы не удалять без отдельной проверенной rollback-миграции.

## Manual testing checklist

- `/start` работает;
- список конкурсов открывается;
- карточка конкурса отображается правильно;
- создание конкурса работает;
- изменение конкурса работает;
- удаление конкурса работает;
- заявки продолжают сохранять выбранный конкурс;
- FAQ и административное меню работают;
- существующие конкурсы не публикуются на сайте автоматически.
